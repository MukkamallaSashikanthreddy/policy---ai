# PolicyLens Architecture Notes

## Components and responsibilities

| Component | Input | Output | Responsibility |
|---|---|---|---|
| Streamlit UI | PDFs, question, scenario, incident facts | User-facing views | User interaction and workspace/session selection |
| Ingestion service | PDF bytes + document metadata | Stored PDF, chunks, index records | Coordinates ingestion, storage and cleanup |
| PyMuPDF extractor | PDF bytes | `{page_number, text}` records | Preserves page boundaries for reliable citations |
| LangChain splitter | Page text | overlapping chunks | Keeps each chunk associated with the page it came from |
| Sentence Transformer | Text | normalized dense vector | Local semantic representation |
| ChromaDB | vectors, chunk text, metadata | nearest chunks | Persistent vector retrieval |
| SQLite | document/session/message records | metadata and history | Relational metadata and conversation persistence |
| Gemini service | evidence bundle and task prompt | Pydantic output | Natural-language answer and structured extraction |
| Citation validator | model evidence IDs + retrieved IDs | validated citation set | Prevents fabricated source IDs/pages from reaching UI |

## RAG data contract

Every stored chunk has at least:

- `document_id`: internal ID used to delete all chunks from one uploaded file.
- `source`: original uploaded filename.
- `policy_group`: workspace used to isolate retrieval between policies.
- `document_type`: policy wording, schedule, add-on, claim guide or other.
- `page_number`: one-based source PDF page number.
- `chunk_index`: index inside the document's extracted pages.
- `clause_type`: keyword-derived label such as coverage, exclusion, deductible or claim documents.

The source and page are copied from stored chunk metadata, never generated by Gemini.

## Trust boundaries

1. Original PDF text is untrusted data. A malicious PDF might contain instructions intended to manipulate the model. Prompts tell Gemini to ignore those instructions and use the text only as policy evidence.
2. Gemini output is also untrusted until Pydantic validates its shape and the citation validator checks every evidence ID against the retrieved set.
3. A valid citation means the source chunk was retrieved and named by the model. It does not prove that the model's interpretation is legally correct; source passages must still be reviewed.
4. Retrieved excerpts are transmitted to the configured Gemini API. Local Chroma/SQLite storage does not mean the full workflow is offline.

## Main failure modes

- Password-protected, damaged or scanned PDFs: rejected during extraction with an actionable message.
- No indexed chunks in selected workspace: the RAG service abstains without calling Gemini.
- Gemini key missing or API unavailable: the UI surfaces the error; the application data remains local.
- Model returns IDs not present in retrieved evidence: those IDs are discarded. A purported grounded answer with no valid evidence IDs is replaced with a warning.
- Missing or ambiguous clauses: the answer/analysis should state insufficiency and prompt for insurer confirmation.
